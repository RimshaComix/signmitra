### 2. Project Purpose & Problem Being Solved
SignMitra is designed to solve the critical **"Counter Communication Divide"** experienced by Deaf and Hard-of-Hearing (DHH) citizens who communicate natively through Indian Sign Language (ISL). 

At physical public service counters (hospital outpatient registration desks, bank tellers, university administrative counters, and transit ticket windows), interactions are fast-paced, high-stress, and reliant on spoken speech. Public clerks do not understand ISL, and professional sign language interpreters cannot be scheduled for spontaneous, daily counter visits. Deaf citizens are forced to resort to slow handwriting or unstructured phone notes. Counter staff frequently provide vague verbal instructions (*"come back tomorrow morning with the prescribed form"*), leading to missed deadlines, incorrect token queues, and compromised personal privacy.

### 3. Target Users & Real-World Use Cases
- **Primary Users:** Deaf and Hard-of-Hearing citizens in India who use Indian Sign Language and need to interact independently with physical public counters.
- **Secondary Users:** Public desk staff, clerks, hospital triage nurses, and bank tellers who have zero training in sign language.
- **Real-World Scenarios:**
  1. *Hospital OPD / Pharmacy:* Presenting symptoms without shouting across a crowded lobby, requesting diagnostic scans, handing in prescription chits, and confirming medicine collection counters.
  2. *Bank Branch:* Lodging failed UPI / NEFT reversal requests, requesting KYC address/mobile updates, depositing cash, or reporting an ATM issue with structured data cards.
  3. *College Office / University:* Resolving exam mark discrepancies, submitting re-evaluation requests, applying for bonafide certificates, and tracking scholarship disbursements.
  4. *Transit / Railway Station:* Locating platforms, buying unreserved tickets, and requesting visual conductor stop alerts.
  5. *Emergency:* Displaying a high-contrast emergency card with medical history, blood group, emergency contacts, and an offline QR code.

### 4. What Distinguishes This Implementation from a Basic Demo
- **Deterministic-First Foundation:** The core application does not crash or freeze when offline or when AI API quotas run out. It maintains curated domain phrasebooks, deterministic text simplifiers, and local state machines.
- **Mandatory Human-in-the-Loop Review Gate:** AI outputs (rewrites, translations, OCR scans) are never shown directly to counter staff. They are presented side by side with the original in an editable review gate where the user must click **Approve & Display Card**.
- **Real, Trained Static ISL Fingerspelling Classifier:** Unlike mock projects, the repository contains a trained TensorFlow/Keras neural network (`isl_static_classifier.keras` and `scaler.pkl` in [`backend/isl/model/`](file:///d:/Projects/SignMitra/signmitra/backend/isl/model/)) classifying 23 static ISL alphabet signs from MediaPipe 3D hand landmarks with 99.48% held-out test accuracy.
- **Deterministic Ambiguity Engine:** Rather than blindly trusting an LLM, [`backend/services/ambiguity_service.py`](file:///d:/Projects/SignMitra/signmitra/backend/services/ambiguity_service.py) implements 761 lines of rigorous regex and linguistic heuristics to flag vague relative times (*"tomorrow morning"*), unspecified locations (*"upstairs"*, *"the office"*), and missing documents.
- **Strict Accessibility Design System:** The entire frontend is styled using a dedicated 3-color high-contrast palette (Linen `#FDF1E2`, Amethyst `#AB92BF`, Dolphin `#655A7C`), complete with screen reader announcements, dynamic text scaling, and audio synthesis.

### The Intended User Journey:
1. **Preparation Before Arrival:** The user selects their destination (e.g., Hospital OPD) from the **Communication Hub** (`/communication-hub`) or **Interactive Guide** (`/guide`). The system generates a pre-visit document checklist and opening cards.
2. **At the Counter:** The user opens the **Two-Way Communication Room** (`/conversation` or `/ai-studio`) or a domain card (`/communication?domain=healthcare&intent=appointment_request`). The screen presents a high-contrast card that auto-triggers speech synthesis (TTS) for the clerk.
3. **Staff Response & Transcription:** The clerk speaks into the microphone. The browser's Web Speech API transcribes the speech live into large subtitles labeled with provenance badges (`is_ai: false`). Alternatively, the clerk taps one of six pre-built quick-reply buttons on the **Staff Response** screen (`/staff-response`).
4. **Ambiguity Resolution:** If the clerk says *"Come back tomorrow morning with the receipt"*, the ambiguity engine highlights *"tomorrow morning"* as a vague timeframe and generates clarification question cards (*"Which exact counter?"*, *"What time does the counter open?"*).
5. **Physical Document Ingestion:** If the clerk hands over an appointment slip or token, the user snaps a photo via the **Vision & OCR Suite** (`/ai-studio`), which validates image dimensions via Pillow, extracts structured fields (Token Number, Room, Department), and populates the **Queue Companion** (`/queue-companion`).
6. **Follow-Up & Audit:** Upon transaction completion, confirmed facts and unresolved actions are saved to the **Follow-Up Planner** (`/followups`) and logged in the local SQLite audit ledger.

## G. AI and Intelligent Functionality

### 1. Centralized Multi-Provider AI Architecture
The backend decouples features from specific AI SDKs via [`backend/services/ai_provider.py`](file:///d:/Projects/SignMitra/signmitra/backend/services/ai_provider.py) (1,668 lines). It implements five distinct provider adapters inheriting from `BaseAIProvider`:
1. **`GroqAdapter`:** Primary high-speed provider. Default text model: `llama-3.3-70b-versatile`; vision model: `llama-3.2-11b-vision-preview`.
2. **`GeminiAdapter`:** Uses Google GenAI SDK. Default model: `gemini-1.5-flash` or `gemini-2.5-flash`.
3. **`CerebrasAdapter`:** Ultra-fast text inference (`llama3.1-8b`).
4. **`OpenAIAdapter`:** Supports GPT models via OpenAI REST API.
5. **`OllamaAdapter`:** Fully local private inference (`http://localhost:11434`).

### 2. Real vs Rule-Based vs Deterministic Boundaries
- **Tone Rewriting & Translation:** Truly AI-powered when an API key is provided. Uses structured prompts enforcing strict factual preservation. When unconfigured, falls back to deterministic dictionaries (`curated_dictionary` engine) without inventing words.
- **Ambiguity Detection:** **100% Deterministic Linguistic Rules.** Implemented in [`backend/services/ambiguity_service.py`](file:///d:/Projects/SignMitra/signmitra/backend/services/ambiguity_service.py). Does NOT call an LLM; uses compiled regular expressions to match relative times, vague directions, and missing documents.
- **Lexical Simplification:** **100% Deterministic Rule Engine.** Matches bureaucratic terminology against plain-English substitution tables.
- **Vision Document OCR:** Truly multimodal. Pillow decodes and inspects the image; the base64 payload is passed to Groq or Gemini vision models. If rate-limited (HTTP 429), it returns an explicit failure object (`live_inference_blocked: true`) and never fabricates text.
- **Static ISL Recognition:** **Real, Trained Neural Classifier.** It does NOT use an LLM. It extracts 126 MediaPipe coordinates from the webcam and executes a trained Keras multi-layer perceptron.

### 3. Verified Static ISL Recognition Pipeline Details
From [`backend/isl/README.md`](file:///d:/Projects/SignMitra/signmitra/backend/isl/README.md) and [`backend/isl/model/model_metadata.json`](file:///d:/Projects/SignMitra/signmitra/backend/isl/model/model_metadata.json):
- **Model Architecture:** `Input(126) -> Dense(256, ReLU) -> BatchNorm -> Dropout(0.30) -> Dense(128, ReLU) -> BatchNorm -> Dropout(0.25) -> Dense(64, ReLU) -> Dropout(0.20) -> Dense(23, Softmax)`.
- **Checkpoint Location:** [`backend/isl/model/isl_static_classifier.keras`](file:///d:/Projects/SignMitra/signmitra/backend/isl/model/isl_static_classifier.keras) (288 KB) + [`scaler.pkl`](file:///d:/Projects/SignMitra/signmitra/backend/isl/model/scaler.pkl) (3.6 KB).
- **Supported Signs (23 Static Alphabet Signs):** `A, B, C, D, E, F, G, I, K, L, M, N, O, P, Q, R, S, T, U, V, W, X, Z`.
- **Excluded Signs (3 Dynamic Motion Signs):** `H, J, Y` are explicitly excluded because they require temporal motion trajectories that single-frame static landmark vectors cannot honestly represent.
- **Confidence Gate & Smoothing:** Requires probability $\ge 0.75$ and temporal agreement (3 of the last 5 frames) before prompting user confirmation.

## H. Complete User Workflows

### Workflow 1: Composing & Presenting a Fast Counter Card
1. User navigates to `/healthcare` and clicks **Request Medical Reports**.
2. Route transitions to `/communication?domain=healthcare&intent=medical_reports_request`.
3. Client loads fields from `WORKFLOW_CONFIGS.medical_reports_request`: Patient Name, MRN / Patient ID, Report Category, Time Period.
4. User fills out the form. The state machine transitions to `review`.
5. The review template formats an unambiguous text card:
   ```text
   MEDICAL RECORDS REQUISITION:
   • Patient: John Doe | ID: 98124
   • Records Requested: Lab Transcripts
   • Period: Last 3 Months
   Please verify records and provide written collection instructions.
   ```
6. User clicks **Present to Staff**. Full-screen high-contrast card renders.
7. System triggers `window.speechSynthesis.speak()` with clear counter voice.
8. Hearing clerk reads screen and clicks quick reply chip: *"Reports ready. Collect at Counter 4"*.
9. State machine transitions to `completed` and logs to `localStorage.getItem('signmitra_history')`.

### Workflow 2: Multimodal Document Ingestion & Queue Token Parsing
1. User receives an appointment chit at hospital reception and navigates to `/ai-studio` (Vision & OCR Tab).
2. User snaps a picture or drags and drops the image into `VisionSuite.js`.
3. Client converts the image to base64 and issues a `POST` request to `/api/vision/analyze` with mode `queue`.
4. Next.js route handler forwards the payload to FastAPI `POST /api/vision/analyze`.
5. `ocr_service.py` validates the payload via Pillow (format, ≤5MB, dimensions ≥50px).
6. Multi-provider adapter routes base64 data to Groq `llama-3.2-11b-vision-preview` (or Gemini).
7. Model extracts structured JSON:
   ```json
   {
     "token_number": "A-42",
     "counter_room": "Room 104",
     "department": "General Medicine",
     "estimated_time": "10:30 AM"
   }
   ```
8. Result appears in the **Review Gate**. The user verifies the values and clicks **Confirm & Save to Queue Companion**.
9. Data is written to `localStorage.getItem('signmitra_active_token')` and displays on `/queue-companion`.

### Workflow 3: Live Real-Time ISL Fingerspelling Recognition
1. User opens `/ai-studio` and selects the **ISL Lab** tab (`ISLLab.js`).
2. Client initializes `@mediapipe/tasks-vision` HandLandmarker with webcam stream in selfie-mirrored mode.
3. User signs the letter **'C'**.
4. MediaPipe extracts 21 3D coordinates per hand.
5. `handToWristRelativeMirrored()` normalizes coordinates relative to the wrist (landmark 0).
6. Client packs 126 floats and issues a `POST` to `/api/isl/predict`.
7. Route handler forwards to FastAPI `POST /predict`.
8. `ISLStaticPredictor` scales features with `scaler.pkl` and evaluates `isl_static_classifier.keras`.
9. Softmax produces probability `0.98` for class `'C'`.
10. `TemporalPredictionSmoother` verifies 3 of last 5 frames agreed on `'C'`.
11. UI presents confirmation modal: `[ Recognized Sign: 'C' (98%) ] -> [ Confirm ] / [ Try Again ]`.
12. Upon user tap on **Confirm**, the character is appended to the communication message draft.

## J. Security, Reliability, and Privacy

1. **Zero Biometric & PII Harvesting:** Counter sessions and interaction logs store communication telemetry (`duration_seconds`, `vague_replies_blocked`, `outcome`), explicitly stripping out Aadhaar numbers, PAN cards, and intimate medical details.
2. **Local-First Data Sovereignty:** Session histories, follow-up planners, and emergency contact details are stored in client-side `localStorage` and local SQLite (`signmitra.db`). No cloud telemetry tracks user movements.
3. **Mandatory Human Approval Gate:** No AI output reaches counter staff or the follow-up planner automatically. Every suggestion must be confirmed by the user.
4. **Credential Protection:** API keys (`GROQ_API_KEY`, `GEMINI_API_KEY`, `CEREBRAS_API_KEY`, `OPENAI_API_KEY`) are loaded strictly server-side by FastAPI and masked from all client payloads and logs.
5. **Deterministic Offline Survivability:** Core phrasebooks, text simplification, emergency display cards, and interaction workflows run 100% locally in the browser without requiring any network connection or API key.
6. **Input Sanitization:** Image uploads are strictly validated through Pillow for file integrity, dimensions, and size (≤5MB) before entering the AI pipeline.

## 4. Final Executive Summary & Facts to Personally Confirm

### A. The Verified Official Project Title
- **Short Name:** `SignMitra`
- **Application Display Title:** `SignMitra - Deaf Accessibility Assistant`
- **Full Descriptive Academic Title:** **`SIGNMITRA - AN ACCESSIBLE COUNTER-COMMUNICATION COMPANION FOR INDIAN SIGN LANGUAGE (ISL) USERS`**

### B. Concise but Complete Explanation of the Project
SignMitra is an accessible, hybrid web application designed to bridge the severe communication divide between Indian Sign Language (ISL) users and hearing desk staff at physical public counters (hospitals, banks, universities, transit hubs). It replaces unstructured, error-prone handwriting with turn-based **Fast Counter Cards**, synchronized **two-way speech-to-text subtitles**, client-side **document and token Vision OCR**, and a **deterministic ambiguity detection engine** that catches vague instructions before errors occur. To provide an honest, accessible signing practice tool, it incorporates a **real, trained static ISL fingerspelling neural classifier** running on MediaPipe 3D hand landmarks for 23 alphabet signs. The system guarantees high resilience via a multi-provider AI fallback tier (Groq, Gemini, Cerebras, Ollama) and operates offline using local phrasebooks, browser storage, and an embedded SQLite audit ledger.

### C. Complete List of Genuinely Implemented Features
1. Fast Counter Cards for Healthcare, Banking, Education, Transport.

4. Static ISL Fingerspelling Recognition via MediaPipe and Keras classifier.
5. ISLRTC Sign Reference Catalog & Learning Flashcards.
